# Upstream issue comparison

Reviewed: 2026-10-14. Codex baseline: v1.3.0, commit `688756f6e36159682f11c44ab28c96e94687ae5b`.

All 47 non-PR issues returned by the upstream GitHub API with `state=all` were reviewed, including closed issues.
Issue state below is the observed API state, not a claim that an upstream defect persists today.
Comparison uses issue reports, our current source and existing tests, plus synthetic policy probes.
It does not establish upstream fix commits or reproduce Claude host behavior. Empty reports are not treated as instructions.

## Findings that affect this plugin

- **P1: parser correctness.** Mixed quote stripping is reproduced in `policy.frontmatter`. A description whose intended value is `'Use when testing'` loses its single quotes when wrapped in double quotes.
- **P1: admission false positives.** `policy.DANGEROUS` flags legitimate examples containing `exec(` or `eval(`. Keep automatic script admission disabled while separating descriptive code from executable instructions.
- **P1: CI discovery guard.** `unittest discover` returns success for an empty suite. Add an explicit nonzero/minimum-count check; current passing tests do not close this future regression path.
- **P1: privacy regression coverage.** Whole PEM redaction and marker idempotence work in synthetic probes. Add escaped, incomplete, clipped and split-record fixtures. Credit-card redaction is absent; implement validated detection with identifier negative cases. No confirmed PEM-body leak was reproduced here.
- **P2: semantic duplicates and scope policy.** Leases/receipts solve overlapping publication, not equivalent lessons under different names. Git-root binding solves normal subdirectories, not every non-Git/submodule scope policy.
- **P2: observability and integration evidence.** Add opt-in safe completion/rejection notifications and a reproducible real-model lifecycle runbook. Native packaging smoke is not proof of assistance quality or every host hook-trust flow.

No runtime fix is shipped by this documentation update. The planned work is prioritized in [ROADMAP.md](../ROADMAP.md).
